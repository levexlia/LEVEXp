# LEVEXp

**LEVEX** — игра, связанная с реальной жизнью: платформа знаний, самовыражения и воплощения целей. За выполненные задачи, достигнутые цели и добро для других — уровень, предметы, бонусы и навыки. Цель — помочь навести порядок в потребностях во всех сферах жизни, в виде RPG.

## Статус v1

Полное видение есть; строим итеративно. Сейчас: один игрок, каталог сфер жизни, цели и XP (не больше 50 за одну цель), виртуальная комната с фотографиями и страница этой комнаты. Состояние лежит в JSON-файле и переживает перезапуск API. Загруженная картинка лежит рядом, в каталоге `uploads` у того же файла, и тоже переживает перезапуск. Аккаунтов нет — игрок один на файл. Модули ниже — дорожная карта, не готовый продукт.

## Дорожная карта модулей

**Ядро**
1. Профиль игрока (аватар, уровень, XP, титулы)
2. Сферы жизни (здоровье, работа, отношения, финансы, творчество, дух и др.)
3. Цели и задачи (создание, дедлайны, чекин выполнения)
4. Прогрессия (XP, уровни, навыки, предметы, бонусы)
5. Добродетель / помощь другим (задания «для других», репутация)

**Социальное и самовыражение**
6. Лента / витрина достижений
7. Сообщества и менторы
8. Чаты / поддержка

**Платформа знаний**
9. Контент и курсы по сферам
10. Оценка прогресса (рубрики, mastery)

**Система и доверие**
11. Авторизация и аккаунты
12. Уведомления и напоминания
13. Админка / модерация
14. Аналитика «порядок в жизни»
15. API + мобильный/веб-клиент

## Структура

```
apps/api         — Fastify API (TypeScript, tsx), JSON-хранилище и файлы фото
apps/web         — страница комнаты (Vite, React, TypeScript)
packages/domain  — типы: Player, LifeSphere, Goal, Artifact, Room, Progression; каталог сфер
```

## Запуск

Node.js 22 (LTS) или новее — то же требование в поле `engines` файла `package.json`. GitHub Actions на push и pull request в `main` ставит Node.js 22 и запускает `npm ci`, `npm run typecheck`, `npm test`.

```bash
cp .env.example .env
npm install
npm run dev:api     # или npm run start:api, http://localhost:3000
npm run dev:web     # http://localhost:5173
curl localhost:3000/health
curl localhost:3000/player
npm test
npm run typecheck
```

## Веб

Страница комнаты — `apps/web`. Два процесса: API и Vite.

`npm run dev:web` проксирует на API пути `/health`, `/player`, `/goals`, `/artifacts`, `/room`, `/progress`, `/spheres` и `/uploads`. Страница и картинки открываются с одного origin, отдельный CORS не нужен. Куда проксировать, задаёт `LEVEX_API` (по умолчанию `http://127.0.0.1:3000`).

На странице: ник, уровень и XP; новая цель сферы «творчество»; фото — вставленная ссылка или файл; кнопка вешает фото в комнату и, если цель ещё открыта, закрывает её. Награду выбирает сервер (10 XP, с фото — 15) и начисляет один раз. Стена показывает размещения и картинки.

Обновление страницы читает ту же комнату. Остановка API и снова `npm run dev:api` с тем же `DATA_FILE` тоже: `GET /room` возвращает то же фото. Внешняя ссылка — это строка в JSON. Файл с `POST /uploads` — байты в каталоге `uploads` рядом с `DATA_FILE` и URL `/uploads/<имя>` в `imageUrl`. Пока на месте и JSON, и этот каталог, картинка на стене та же. При запуске через npm это `apps/api/data/levexp.json` и `apps/api/data/uploads/`.

## Хранение

Один JSON-файл. Путь задаёт `DATA_FILE`; если переменной нет, берётся `./data/levexp.json` относительно рабочей директории процесса. `npm run start:api` запускает скрипт в `apps/api`, поэтому файл по умолчанию — `apps/api/data/levexp.json`. Каталог создаётся при первой записи. Данные в корне репозитория: `DATA_FILE=../../data/levexp.json`.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | порт HTTP |
| `DATA_FILE` | `./data/levexp.json` | игрок, цели, XP, фото и комната |

Загруженные картинки в этот JSON не входят. Они лежат в каталоге `uploads` в той же папке, что и `DATA_FILE`. Для пути по умолчанию это `./data/uploads` относительно процесса API, то есть `apps/api/data/uploads/`, если API запущен через npm. Каталог `data/` в git не входит. Перезапуск с тем же `DATA_FILE` отдаёт те же `imageUrl`, а `GET /uploads/<имя>` читает тот же файл с диска — поэтому фото остаётся в комнате.

Файл читается при старте и перезаписывается целиком после создания цели, первого выполнения, первой привязки фото к цели, создания фото и `PATCH /player` (сначала временный файл, затем `rename`). Создание цели, выполнение и создание фото меняют память только после успешной записи: если запись не удалась, ни цель, ни XP, ни привязка в памяти не остаются, а повторный запрос выполняет операцию заново. Повторное выполнение уже закрытой цели само по себе диск не трогает.

Если файла нет, создаются игрок с ником `Player` и две открытые демо-цели — XP за них ещё не начислен. Если в файле есть цели, но нет игрока, добавляется только игрок: опыт не пересчитывается из списка целей, источник XP — `player.progression`. Повреждённый JSON не перезаписывается, процесс завершается при загрузке.

```json
{
  "version": 1,
  "player": {
    "id": "…",
    "nickname": "Player",
    "createdAt": "2026-01-01T00:00:00.000Z",
    "progression": { "level": 1, "totalXp": 0, "xpBySphere": {} }
  },
  "goals": [],
  "artifacts": [],
  "room": { "placements": [] }
}
```

Файл, записанный до комнаты, без ключей `artifacts` и `room`, читается как пустая комната и не переписывается, пока не случится следующее изменение. В `room.placements` лежит только `artifactId`. Само фото — в `artifacts`, в том же порядке, в каком его создали. `imageUrl` и `goalId` попадают в объект фото, только когда они заданы.

`title` и `avatarUrl` попадают в объект, только когда они заданы. При чтении `level` считается из `totalXp`: `floor(totalXp / 100) + 1`, даже если в файле записано другое число.

## API v1: Игрок

Один игрок на файл. `id` и `createdAt` задаются при создании и через API не меняются.

`progression` — то, что лежит на диске (`level`, `totalXp`, `xpBySphere`). `progress` — тот же прогресс в форме `GET /progress`: `xp` равен `progression.totalXp`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/player` | игрок и прогресс |
| PATCH | `/player` | изменить `nickname`, `title`, `avatarUrl` |

`PATCH` принимает JSON без лишних полей и хотя бы с одним полем. Непереданные поля не меняются. Ответ `200` — тот же объект, что у `GET /player`. Невалидное тело — `400`.

| Поле | Правило |
|---|---|
| `nickname` | строка 1–32 символа после обрезки пробелов по краям |
| `title` | строка 1–64 или `null` (убрать титул) |
| `avatarUrl` | строка 1–2048 или `null` (убрать аватар) |

```bash
curl localhost:3000/player
curl -X PATCH localhost:3000/player -H 'content-type: application/json' \
  -d '{"nickname":"Ася","title":"Следопыт"}'
```

## API v1: Цели + XP

Цели и XP читаются из того же JSON-файла, что и игрок.
Формула уровня: `level = floor(xp / 100) + 1` (0–99 XP → 1, 100–199 → 2 …), см. `levelForXp` в `packages/domain`.

XP — поощрение за сделанное дело, а не оценка мастерства. Будущие навыки (`skills`) — отдельная линия: они не считаются из `xpReward` или `xpForGoal` и в этом срезе их нет.

Награду новой цели назначает сервер, чистая функция `xpForGoal` в `packages/domain`. Клиент не выбирает `xpReward`: поле в `POST /goals` — `400` `{ error: "xpReward is set by the server" }`. Отдельного `PATCH` награды нет.

| Ситуация | XP |
|---|---|
| обычная цель (любая сфера или без сферы) | 10 (`XP_REWARD_STANDARD`) |
| цель сферы `creativity` с привязанным фото | 15 (10 + `XP_CREATIVITY_PHOTO_BONUS`) |

Каждое такое начисление — целое от 1 до 50 (`XP_REWARD_MAX`). Общий XP игрока этим потолком не ограничен.

Цель, уже лежащая в файле со своим `xpReward`, при выполнении не пересчитывается через `xpForGoal`. Начисляется сохранённое число, но не больше 50 (`xpGrantedForGoal`): старая награда 10000 даёт 50, награда 30 по-прежнему даёт 30. Бонус за фото прибавляется только к стандартной награде 10 у цели `creativity`. После успешного выполнения в цели записывается фактически начисленное число. Две старые награды по 10000 дают 50 + 50 = 100 XP и уровень 2. Повторное выполнение не начисляет снова.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | статус |
| GET | `/goals` | список целей |
| POST | `/goals` | `{ title, sphere? }` → `201` + цель. `xpReward` в теле — `400` |
| POST | `/goals/:id/complete` | отметить выполненной. Тело необязательное: `{ artifactId? }` привязывает фото из комнаты к цели сферы `creativity`. XP начисляется один раз по правилам сервера → `{ goal, progress }` (`404`, если нет цели) |
| GET | `/progress` | `{ xp, level, xpBySphere }` |

`sphere` — id из каталога сфер (см. ниже). Цель без сферы увеличивает только общий `xp`. Лишние поля в теле — `400`.

`artifactId` проверяется до начисления XP. Неизвестное фото — `400` `{ error: "artifact not found" }`. Цель не из сферы `creativity` — `400`. Фото уже привязано к другой цели — `409` `{ error: "artifact is linked to another goal" }`, цель остаётся открытой. Повторная привязка того же фото к той же цели ничего не меняет.

```bash
curl localhost:3000/goals
curl -X POST localhost:3000/goals -H 'content-type: application/json' \
  -d '{"title":"Пробежка 5 км","sphere":"health"}'
curl -X POST localhost:3000/goals/<id>/complete
curl localhost:3000/progress
```

## API v1: Комната и фото

Одна комната на файл. Фото появляется в ней в момент создания и остаётся после выполнения цели. Сфера фото всегда `creativity`.

Петля: создать цель сферы `creativity` (награда 10) → добавить фото с `goalId` этой цели (награда становится 15) → выполнить цель (XP один раз) → `GET /room` показывает ту же фотографию. Фото можно создать и без цели, а привязать его телом `POST /goals/:id/complete`: бонус попадает в то же начисление. Фото, привязанное после выполнения, XP не увеличивает.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/artifacts` | фото в порядке создания |
| POST | `/artifacts` | `{ title, kind, imageUrl?, goalId? }` → `201` + фото. `kind` сейчас только `photo`. Фото сразу ставится в комнату |
| GET | `/room` | `{ placements: [{ artifactId, artifact }] }`. `artifact` — то же фото, что в списке; в файле хранится только `artifactId` |

| Поле | Правило |
|---|---|
| `title` | строка 1–200 после обрезки пробелов по краям |
| `kind` | `photo` |
| `imageUrl` | необязательная строка 1–2048 после обрезки пробелов. Внешняя ссылка или URL из `POST /uploads` |
| `goalId` | необязательный id цели сферы `creativity`. Чужой id или другая сфера — `400` |

Загрузка файла: `POST /uploads`, multipart, поле `file`. PNG, JPEG, GIF или WebP, не больше 5 МБ. Формат определяется по байтам, заголовок `Content-Type` не принимается на веру. Ответ `201` — `{ "url": "/uploads/<uuid>.<ext>" }`. Файл пишется в `<каталог DATA_FILE>/uploads`. `GET /uploads/<имя>` отдаёт этот файл. Чужое имя — `400`, нет файла — `404`. Не картинка, пустой файл или тело не multipart — `400`. Слишком большой файл — `400` `{ error: "file is too large" }`.

В JSON хранится только URL. Комната после перезапуска показывает то же фото, если на месте и `DATA_FILE`, и каталог `uploads` рядом с ним.

```bash
curl -X POST localhost:3000/goals -H 'content-type: application/json' \
  -d '{"title":"Нарисовать окно","sphere":"creativity"}'
curl -F "file=@photo.png;type=image/png" localhost:3000/uploads
curl -X POST localhost:3000/artifacts -H 'content-type: application/json' \
  -d '{"title":"Утренний свет","kind":"photo","imageUrl":"/uploads/<uuid>.png","goalId":"<goal-id>"}'
curl -X POST localhost:3000/goals/<goal-id>/complete
curl localhost:3000/room
curl -o copy.png localhost:3000/uploads/<uuid>.png
```

## API v1: Сферы жизни

Каталог фиксированный: `LIFE_SPHERES` в `packages/domain`. Он не пишется в `DATA_FILE` и не меняется между рестартами. Порядок `GET /spheres` — порядок каталога. `id` стабильный, `name` и `description` — текст для интерфейса.

| id | name |
|---|---|
| health | Здоровье |
| mind | Разум |
| career | Карьера |
| finance | Финансы |
| relationships | Отношения |
| creativity | Творчество |
| spirit | Дух |
| community | Сообщество |

| Метод | Путь | Описание |
|---|---|---|
| GET | `/spheres` | каталог сфер |
| GET | `/spheres/:id` | одна сфера (404 `{ error: "sphere not found" }`, если id нет в каталоге) |

`progress.xpBySphere` — объект `{ [sphereId]: number }` только для сфер, по которым уже начислен опыт. При первом выполнении цели с `sphere` в эту сферу добавляется начисленный XP (повторное выполнение не начисляет). Сумма значений `xpBySphere` может быть меньше общего `xp`, если часть целей была без сферы. Нулевые сферы в объект не входят: для полного списка соедините каталог с этой картой.

```bash
curl localhost:3000/spheres
curl localhost:3000/spheres/health
```
